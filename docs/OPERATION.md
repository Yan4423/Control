# 遥控操作与排障

## 每次启动

1. 履带架空、摇杆回中，SA放禁止侧；先只接C板逻辑电源。
2. 打开USB转TTL仪表，确认不断收到CSV。LINK应为绿，ENABLE/ARMED应为灰，C3–C6应全部为0。
3. 核对失联/禁止状态和输出后再接电机12V。
4. 摇杆保持中位，将SA拨到允许侧。两杆中位时应保持零输出；轻推油门看两个电机方向。
5. 需要停止时将SA拨禁止；若行为异常，断开电机动力电源。

**当前代码没有中位解锁互锁**：只要先收到过SA禁止，再拨允许，即使摇杆带油门也会解锁并渐变输出。上电SA已允许时不会直接解锁。恢复失联后必须重新经历禁止→允许。

SA允许方向以仪表 `sa_raw > 1024` / ENABLE为准；历史调试时通常是SA下拨，但接手人更改遥控器映射后不应只记物理朝向。

## 渐变与方向

- 指令范围-1000到1000，左右目标分别为 `throttle+turn` 与 `throttle-turn`，各自限幅。
- 每10ms最多变化5，0→1000约2秒；最大实际PWM为50%。从正满到负满约4秒，软件先过零再反向。
- 油门回中使用同样的渐变减速。SA禁止和失联处理会绕过渐变直接清零。
- 软件指令过零不能证明转子已停止；目前没有转速闭环或“机械静止才能换向”的检测。
- 当前前推：C3、C6有效；后拉：C4、C5有效。转向方向受遥控通道正负和实物安装影响，必须架空核验。
- 开环PWM不保证两边速度相同。不能把“50%占空比”理解成“50%转速”。

## 打开仪表

Windows使用自带Windows PowerShell 5.1和WinForms：

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File tools/serial_dashboard.ps1 -PortName COM7
```

COM7只是例子。可用 `[System.IO.Ports.SerialPort]::GetPortNames()` 查本机端口。双击 `tools/Open Serial Dashboard.cmd` 会自动检测；多个端口时需显式传入COM名。仅本次进程使用ExecutionPolicy Bypass，不修改系统策略。

仪表显示：T为油门归一化指令；L/R是经过渐变与电机极性后的电气命令，所以直行时可能一正一负。C3/C4是左侧，C5/C6是右侧；PWM曲线读右侧计数纵轴，命令读左侧纵轴；横轴为板上时间秒。仪表显示的是MCU比较寄存器值，不是实际针脚波形或电机端电压。

## 常见问题

| 现象 | 先查 |
|---|---|
| 仪表无法打开COM | 端口是否存在、其他程序是否占用、是否用了正确的USB转TTL设备 |
| WAITING FOR DATA | USART6的PG14→RXD、共地、115200 8N1、C板正在运行、固件版本；连接COM不等于有数据 |
| LINK灰，原始通道为0 | RF206S供电/绑定/W.BUS模式、PC11信号路径、100000 8E2、DMA/USART中断 |
| ENABLE绿而ARMED灰 | 先禁止再允许；检查LINK是否间断、接收机Failsafe、UART错误计数 |
| ARMED偶发掉线 | 记录CSV与W.BUS故障标志；也检查维护文档中的时间戳并发审查项 |
| PWM显示非零但不转 | 波形是否到达正确针脚、逻辑共地、B+/B-动力电源、VCC与R_EN/L_EN、驱动/电机线是否导通 |
| 测量有频率但占空比不对 | 频率和占空比是不同量。应测20kHz及0–50%，禁止时0Hz可能正常 |
| 最大指令却只有一侧转 | 查左右驱动使能、C3–C6映射、断线；不要只因寄存器值正确就排除硬件 |
| 编码器一直为0 | 核对PF0/PF1接线、电平、供电和中断；断动力后手动转动左侧 |
| 右侧无编码器显示 | 当前未实现，详见交接待办 |

调试链路按顺序定位：原始输入 → LINK/ENABLE/ARMED → 电气命令 → CCR → 针脚波形 → 驱动电源/使能 → 电机 → 编码器。需要恢复旧版本时先看提交中的实际行为；本地旧备份曾包含上电自动转的诊断代码，不要随意烧录。
